# WowLance 2.0 — отчёт для стейкхолдеров

| Поле | Значение |
|------|----------|
| **Дата** | 2026-10-21 |
| **Репозиторий** | `WowLance-2.0` (`main`) |
| **Канон** | [ADR-002](ADR-002-wowlance-2.0-platform-room.md) |
| **Техническая оценка** | [оценка готовности и качества](261021%20-%20оценка%20готовности%20и%20качества.md) |

---

## Одним абзацем

WowLance 2.0 — это **рабочая комната** платформы: команда, снимок стратегии, задачи, лиды до Hot.  
Сервис **уже можно показывать на демо** и стыковать соседям по контрактам.  
В «боевую» платформу он войдёт, когда Strategy / Order / Talent / CRM / Keycloak отдадут live-эндпоинты — узкое место сейчас **не скорость комнаты**, а готовность соседей.

---

## 1. Что уже сделали

За ~две недели (с ~10.10) закрыт вертикальный контур комнаты на заглушках — фазы **C0–C25** в коде, **~140 коммитов**, **21 контракт OpenSpec**, **~180 автотестов**, QA по золотому пути.

### Для бизнеса (можно показывать)

| Возможность | Зачем это нужно |
|-------------|-----------------|
| Вход из Стратегии (FounderHandoff) | Кнопка «в WowLance» создаёт комнату со снимком стратегии |
| «Оплата» пакета (entitlement) | Набор команды включается только после разрешения Order |
| Экран комнаты | Фаундер / тимлид видят снимок, слоты, задачи, лиды, чат, meet |
| Слоты + roster + назначение | Проверенные люди садятся на роли; можно снять / переназначить |
| Обновление стратегии | Тимлид Accept / Reject; при Accept слоты **пересобираются** под новый план |
| Подбор кандидатов (Matching lite) | Shortlist из локального roster на слот (без live Talent) |
| Задачи + Quality Gate | Сдача с доказательством, приёмка / отклонение |
| «Я заработал» + сводка в health | Начисления в комнате и блок earned в снимке для Стратегии |
| Hot → CRM + статус сделки обратно | Горячий лид уходит наружу; CRM может вернуть статус сделки |
| Сигналы соседям (outbox) | RoomCreated, StaffingUnlocked, TaskAccepted, health и др. |
| Вход по JWT + внутренний service-token | Готовность к общему логину и к вызовам сервис↔сервис |
| Контракты OpenSpec | Соседи стыкуются по схемам, не по внутренней реализации |

### Чего WowLance намеренно **не** делает

- Не CRM и не Jira  
- Не кабинет аналитики фаундера (это Strategy; WL отдаёт health)  
- Не регистрация пользователей (только Keycloak / платформенный логин)  
- Не выставление счёта за лид (Order — за пакет комнаты)

---

## 2. На чём акцентируемся сейчас

**Цель этапа:** законченный **stub-MVP комнаты** + понятные контракты для соседей.  
Код зрелый для демо и интеграции «по бумаге»; live-адаптеры — следующий горизонт.

| Акцент | Смысл |
|--------|--------|
| **Демо фаундера** | Один сценарий: Стратегия → комната → команда → задачи → Hot → CRM → health |
| **Контракты с соседями** | Зафиксировать поля handoff, entitlement, Hot→CRM, health, JWT |
| **Стабильность stub-пути** | Не ломать золотой путь при доработках RBAC / Gateway |
| **Не раздувать scope** | Matching / rematerialize / chat / meet уже в stub; deep product features — после live-стыковки |

### Пересмотренная оценка (21.10, после C19 + C22–C25)

| Контур | Было (утро 21.10) | Сейчас | Комментарий |
|--------|-------------------|--------|-------------|
| Demo / stub-MVP комнаты | ~85% | **~90%** | Закрыты rematerialize, matching lite, TaskAccepted, earned в health, CRM deal inbound |
| Встраивание в живую платформу | ~45% | **~50%** | Больше контрактов и сигналов; live всё ещё stubs |
| Боевой прод | ~35–40% | **~40%** | Нужны брокер/webhooks, полный RBAC, live Keycloak, hardening |

| Ось | Балл |
|-----|------|
| Готовность demo / stub-MVP | **9 / 10** |
| Готовность live-платформы | **5 / 10** |
| Качество кода и процесс | **7.5–8 / 10** |

## 3. Следующие шаги

### Ближайшие (WowLance, без ожидания соседей)

1. **Упакованный founder-demo** — один чеклист / скрипт показа от кнопки до Hot и health.  
2. **Полный QA-прогон C0–C25** — обновить отчёт после сегодняшних merge.  
3. **C26+ (по приоритету продукта):** полный RBAC ролей в комнате → Gateway → подготовка live-адаптеров.

### Параллельно со смежниками (блокирует «платформу целиком»)

| Сосед | Что нужно от них | Что уже готово у WL |
|-------|------------------|---------------------|
| **Strategy** | Live FounderHandoff + приём health / RoomCreated | Контракты + stubs |
| **Order** | Live entitlement после оплаты пакета | Unlock по stub событию |
| **Talent** | Live roster / matching (если нужен beyond local) | Local roster + Matching lite |
| **CRM** | Приём Hot + отдача deal-status | Hot outbox + inbound stub |
| **Keycloak** | Боевой realm / JWKS | JWT + shadow user + service-token stub |

### Ориентир по срокам

| Горизонт | Ожидание | Условие |
|----------|----------|---------|
| **1 неделя** | Стабильный demo-пакет + QA C0–C25 | Только команда WL |
| **2–4 недели** | Live JWT + live handoff Strategy + entitlement от Order | Sandbox и владельцы контрактов у соседей |
| **4–7 недель** | Hot в выбранную CRM + витрина health в Стратегии | Названа CRM, согласованы поля |
| **Риск сдвига** | +2–4 недели | Нет владельца контракта / смена CRM mid-flight / нет брокера (закрываем webhooks) |

---

## 4. Просьба к стейкхолдерам

1. Подтвердить приоритет: **демо на stubs** vs **ускорение live со Strategy/Order**.  
2. Назначить **владельцев контрактов** у Strategy, Order, CRM, Keycloak.  
3. Зафиксировать **CRM first** для Hot-handoff (чтобы не переделывать поля).  
4. Не расширять комнату в CRM/Jira/регистрацию — границы ADR-002 держат темп.

---

**Итог:** комната WowLance 2.0 **готова к показу и к договорённостям соседей**.  
Следующий большой скачок ценности — не новые экраны в комнате, а **первые live-стыки** с платформой.
