## 3. Готовность по контурам

### 3.1. Уже закрыто (stub-MVP комнаты)

Соответствует ADR-002 на заглушках:

- FounderHandoff + immutable strategy snapshot  
- Entitlement → `staffing_unlocked`  
- Room UI, слоты, roster, assign / unassign / reassign  
- StrategyPublished → Accept / Reject  
- Tasks + Quality Gate + assignee из roster  
- Hot → CRM stub + outbox  
- Outbox: `RoomCreated`, `StaffingUnlocked`, health snapshot и др.  
- JWT + shadow user; internal service-token stub  
- Meet/Jitsi stub, chat stub, earnings stub, termination stub  

Золотой путь (handoff → entitlement → команда → QG → Hot→CRM → health) подтверждён QA.

### 3.2. Ещё не «платформа в бою»

| Дыра | Статус |
|------|--------|
| Live Strategy / Talent / Order / CRM | stubs |
| Боевой Keycloak realm | stub JWKS / paste-token |
| Реальная доставка outbox (брокер / webhook worker) | статус `sent` без шины |
| Полный RBAC ролей в комнате | «valid JWT → пускаем» |
| Matching / rematerialize (C22+) | задания есть |
| Live витрина фаундера в Стратегии | health stub у WL |
| C19 CRM deal inbound | смотреть актуальный `main` / задания |

## 4. Качество кода

### 4.1. Оценка: **7.5 / 10**

Уместна для скорости «стажёр + ИИ + срезы»; для enterprise-prod — рано.

### 4.2. Плюсы

1. Слои `api` → `domain` → `db` / `adapters` (например `domain/handoff.py`).  
2. Contract-first: YAML + examples ведутся рядом с кодом.  
3. Идемпотентность handoff (fingerprint, `already_exists` / 409).  
4. Outbox как заготовка под платформенную шину.  
5. Auth разделён: client JWT vs internal token; fail-fast без секрета в strict.  
6. Тесты на отдельной БД `wowlance_test`, регрессии по срезам.  
7. Frontend: `apiFetch` + панели по фичам.  
8. Задания и QA-отчёты поддерживают воспроизводимый процесс.

### 4.3. Минусы / техдолг

1. RBAC почти отсутствует (зафиксировано в auth: «valid JWT → has sub»).  
2. Outbox без worker / retry / DLQ.  
3. `models.py` разросся; docstring отстаёт от фактических фаз.  
4. UI — каркас, не продуктовый дизайн.  
5. Нумерованные subject коммитов (`8`, `9`, `10`) засоряют историю.  
6. Dual Alembic heads при параллели — риск, хоть merge-миграции есть.  
7. Платформенный CI/lint в этой оценке не подтверждался (локальный pytest сильный).
