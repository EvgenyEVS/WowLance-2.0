## Одним абзацем

WowLance 2.0 — **рабочая комната** платформы: команда, снимок стратегии, задачи, лиды до Hot.  
С ~9 октября сервис собран как отдельный микросервис на stubs: его **можно показывать на демо** и отдавать соседям пакет контрактов на согласование.  
В живую платформу комната войдёт после `agreed` и sandbox у Strategy / Order / Talent / CRM / Keycloak — узкое место сейчас **готовность соседей**, не скорость комнаты.

---

## 1. Что уже сделали

С **начала работ над 2.0** (~09.10) закрыт вертикальный контур комнаты и следующий слой «демо + UX + подготовка к согласованиям»:

| Метрика | Значение |
|---------|----------|
| Фазы в коде | **C0–C33** (далее C34+ — live после `agreed`) |
| Коммитов на `main` | ~150+ |
| Контракты OpenSpec | **22** YAML, разложены по сервисам |
| Автотесты | **201 passed** |
| QA | Золотой путь G1–G10 и прогон C0–C25 (ручной) — зелёные |

### Для бизнеса (можно показывать)

| Возможность | Зачем это нужно |
|-------------|-----------------|
| Вход из Стратегии (FounderHandoff) | Кнопка «в WowLance» создаёт комнату со снимком стратегии |
| «Оплата» пакета (entitlement) | Набор команды — только после разрешения Order |
| Экран комнаты | Снимок, слоты, задачи, лиды, чат, meet; UX-полировка |
| Слоты + roster + matching lite | Назначение, снятие, пересборка после Accept стратегии |
| Задачи + Quality Gate | Сдача с доказательством, приёмка / отклонение |
| «Я заработал» + health | Начисления и сводка для витрины Стратегии |
| Hot → CRM + статус сделки | Горячий лид наружу; CRM может вернуть статус |
| Сигналы соседям (outbox) | RoomCreated, StaffingUnlocked, TaskAccepted, health и др. |
| JWT + service-token + RBAC lite | Общий логин и роли в комнате (stub / lite) |
| Founder-demo пакет | Скрипт показа: handoff → команда → QG → Hot → health |
| Контракты по сервисам | Соседи берут свою папку + реестр, не «весь репозиторий» |

### Чего WowLance намеренно **не** делает

- Не CRM и не Jira  
- Не кабинет аналитики фаундера (это Strategy; WL отдаёт health)  
- Не регистрация пользователей (Keycloak / платформа)  
- Не счёт за лид (Order — за пакет комнаты)

## 2. Готовность контрактов (кратко)

Контракты **готовы к выдаче соседям на review** (`proposed`).  
Подписей `agreed` пока нет — это ожидаемо: сначала пакет, потом согласование.

| Показатель | Статус |
|------------|--------|
| Раскладка по микросервисам | ✅ `strategy/` · `order/` · `talent/` · `crm/` · `keycloak/` · `platform/` · `meet/` · `wowlance/` |
| Сверка с кодом stub | ✅ статус **aligned** в REGISTRY |
| Example JSON для границы | ✅ почти везде (CrmDealStatus — добавить при пинге) |
| Владельцы у соседей | 🟡 шаблон есть ([contracts-owners.md](../guides/contracts-owners.md)), имена **TBD** |
| Статус `agreed` | ❌ ещё нет ни одного |
| Live HTTP / брокер | ❌ не подключены (outbox stub `sent`) |

| Сосед | Пакет на согласование | Что просим |
|------|------------------------|------------|
| **Strategy** | Handoff, StrategyPublished, RoomCreated, RoomHealth | `agreed` на v1 as-is |
| **Order** | EntitlementGranted, StaffingUnlocked | `agreed` (вместо отдельного PaymentSucceeded на границе WL) |
| **Talent** | RosterUpsert, MemberTerminated, TaskAccepted | `agreed` на stub upsert + outbox |
| **CRM** | HotLeadToCrm, CrmDealStatus | `agreed` + фиксация CRM first |
| **Keycloak / Platform** | AuthBearer, InternalServiceAuth | `agreed` на JWT и service-token |
| **Meet** | RoomMeet | `agreed` на stub URL |
| **WowLance (комната)** | `wowlance/*` | **не** на подпись соседям — внутренний API |

Пока нет `agreed` — команда комнаты **продолжает stubs** (demo, UX, RBAC, тесты). Live-адаптеры — только после согласования.

## 3. На чём акцентируемся сейчас

**Цель этапа:** стабильный demo на stubs + выдача контрактов соседям + не раздувать scope до live.

| Акцент | Смысл |
|--------|--------|
| **Согласование границ** | Заполнить владельцев, прогнать пинг, получить `agreed` / ≤5 вопросов |
| **Качество stub-пути** | Не ломать золотой путь; держать pytest зелёным |
| **Демо фаундера** | Один сценарий «кнопка → комната → Hot → health» |
| **Без deep product** | Нет deep CRM / live Talent / Jira до договорённостей |

### Оценка готовности

| Контур | Оценка | Смысл |
|--------|--------|--------|
| Demo / stub-MVP комнаты | **~92%** | Контур C0–C33: демо, RBAC lite, UX, hardening, пакет контрактов |
| Встраивание в живую платформу | **~50%** | Контракты готовы к review; live и `agreed` впереди |
| Боевой прод | **~40%** | Нужны брокер/webhooks, боевой Keycloak, полный hardening |

| Ось | Балл |
|-----|------|
| Готовность demo / stub-MVP | **9 / 10** |
| Готовность контрактов к согласованию | **8 / 10** |
| Готовность live-платформы | **5 / 10** |
| Качество кода и процесс | **8 / 10** |

## 4. Следующие шаги

### Ближайшие (WowLance, без ожидания соседей)

1. Поддерживать **founder-demo** и зелёный pytest.  
2. Добить мелочи UX / hardening по приоритету продукта.  
3. **Не** стартовать C34+ live adapters без `agreed`.

### Параллельно со смежниками

| Действие | Кто |
|----------|-----|
| Назначить владельцев в [contracts-owners.md](../guides/contracts-owners.md) | Стейкхолдеры / тимлиды соседей |
| Выдать пакет: REGISTRY + `contracts/<сервис>/` | Тимлид WL |
| Ответ: `agreed` или ≤5 вопросов | Сосед |
| Sandbox live (после `agreed`) | Strategy → Order → CRM / Keycloak |

### Ориентир по срокам

| Горизонт | Ожидание | Условие |
|----------|----------|---------|
| **1–2 недели** | Первые `agreed` (Strategy / Order) | Назначены владельцы, канал пинга |
| **2–4 недели** | Live JWT + handoff + entitlement | Sandbox у соседей |
| **4–7 недель** | Hot в CRM + витрина health в Стратегии | CRM first зафиксирован |
| **Риск сдвига** | +2–4 недели | Нет владельца / смена CRM / нет брокера |

## 5. Просьба к стейкхолдерам

1. Подтвердить приоритет: **демо на stubs** vs **ускорение live**.  
2. Назначить **владельцев контрактов** (Strategy, Order, CRM, Keycloak) — сейчас TBD.  
3. Зафиксировать **CRM first** для Hot-handoff.  
4. Не расширять комнату в CRM / Jira / регистрацию — границы ADR-002.

---

**Итог:** с начала работ над 2.0 (~09.10) комната **собрана, демонстрируема и готова отдавать контракты на согласование**.  
Следующий скачок ценности — не новые экраны, а **первые `agreed` и live-стыки** с платформой.
