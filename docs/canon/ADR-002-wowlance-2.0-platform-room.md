## Для оунера — в двух минутах

**WowLance** — универсальная **рабочая комната**: команда, инструкции, задачи, контроль исполнения (продажи и лёгкая разработка в одном каркасе). Крупные многокомандные проекты — не цель.

**Путь фаундера**

1. Разрабатывает стратегию в сервисе **Стратегия**.  
2. Жмёт «Перейти в WowLance…» — в комнату уходит **зафиксированная версия** стратегии и документов.  
3. **Основную аналитику** по комнате (WowLance) и по продажам (**CRM**) смотрит **в Стратегии** — один кабинет результатов.  
4. Если нужны детали команды — кнопка вроде **«Как дела у команды»** → WowLance (задачи, операционка, подробная статистика комнаты).

Менять стратегию после старта **не поощряем**. Если новая версия всё же появилась — **тимлид** получает уведомление и **принимает или отклоняет**.

Горячий лид уходит в **CRM**; менеджер работает там. Оплата **пакета комнаты** — через Order / Payments платформы.

---

## Границы (коротко и жёстко)

**У каждого сервиса своя база данных.** Сервисы не читают таблицы друг друга. Связь — по ID пользователя (Keycloak) и по контрактам (API / события).

**Входит в WowLance:** комната, команда, снимок стратегии, задачи и отчёты, лиды до Hot и передача в CRM, roster фрилансеров, обзор/операционка для тимлида и команды.

**Не входит в WowLance:**

| Не входит | Где живёт |
|-----------|-----------|
| **Jira** | Вне платформенного ядра комнаты (в 2.0 не подключаем как обязательную часть) |
| **CRM** | Отдельный сервис; после Hot менеджер работает в CRM |
| Редактор стратегии фаундера | Сервис **Стратегия** |
| Верификация / стажировка фрилансеров | **Talent** |
| Счета и заказы за пакет комнаты | **Order / Payments / Invoicing** |
| Видеозвонки | **Jitsi** (или Meet платформы) — по ссылке |

Файлы (SOP, вложения): общий **object storage** платформы, у каждого сервиса свой префикс; **версия документа — в пути**. Это не «одна БД», а общее файловое хранилище.

---

## Контекст

1. Исходное ТЗ (`010101`) описывало единый продукт целиком; схемы микросервисов в нём не было.  
2. Платформа: Keycloak, API Gateway, FastAPI, React, PostgreSQL на сервис, OpenSpec.  
3. В репозитории есть домен комнаты 1.0 (роли, задачи, Hot, staffing) на Django — его смыслы переносим, стек деплоя меняем.  
4. Нужен один документ границ для оунеров, команды и ИИ.

---

## Решение

**WowLance 2.0 — сервис универсальной комнаты исполнения.**

### 1. Кабинет фаундера и аналитика

| Что | Где |
|-----|-----|
| Стратегия, SOP, запуск в WL | **Стратегия** |
| Основная аналитика по WL + CRM | **Стратегия** (сводки по API/событиям из WL и CRM) |
| Подробная статистика команды, задачи, операционка | **WowLance** по кнопке «Как дела у команды» (SSO) |
| Ведение сделки после Hot | **CRM** |

Стратегия для фаундера — **витрина результатов**, не замена комнаты и не CRM.  
WowLance отдаёт в Стратегию **агрегаты здоровья комнаты** (read-модель / события), не открывает свою БД на чтение.

### 2. Стратегия → комната (данные)

- Handoff: версионированный **снимок** в PostgreSQL WowLance + URI файлов (**версия в пути**).  
- Чужую БД Стратегии не читаем.  
- Целевая модель данных: Hybrid (C); первый срез может быть чистым снимком (A). Live-only без снимка (B) — не default.

**После старта**

1. UX не провоцирует правки стратегии.  
2. Событие «опубликована новая версия» → уведомление **тимлиду**.  
3. Тимлид: **Accept** / **Reject**.  
4. До Accept комната на прежней версии.

### 3. Люди

- Keycloak; в WowLance — shadow-пользователь с тем же `sub`.  
- Фрилансеры только после Talent → локальный **roster**; подбор по своей БД.

### 4. Продажи

- В комнате: работа до **Hot** (SDR).  
- Hot → handoff в CRM + ссылка.  
- Воронку сделки и счета лиду в WowLance не делаем.  
- Сводки продаж для фаундера стекаются в **Стратегию** (из CRM), не обязаны дублироваться тяжёлым UI в WL.

### 5. Деньги платформы

- Order / Payments / Invoicing ↔ WowLance: пакет комнаты, слоты, entitlement.  
- Счёт конечному лиду — контур CRM.

### 6. Задачи по ролям

| Роль | Где работает |
|------|----------------|
| Фрилансер | Простой трекер в WL; «я заработал» — контур WL |
| Тимлид | Вся операционка WL + Accept стратегии |
| Фаундер | Аналитика в Стратегии; в WL — по желанию «как дела у команды», без ежедневной доски задач |

Jira в продукт 2.0 **не входит**. Простого трекера комнаты достаточно для малых sale/develop проектов.

### 7. Стек и обмен (команда / ИИ)

| Слой | Выбор |
|------|--------|
| API | FastAPI за API Gateway |
| UI | React |
| БД | **Своя** PostgreSQL на сервис WowLance |
| Auth | Keycloak JWT; между сервисами — client credentials / token exchange |
| Синхронно | HTTPS + JSON (OpenAPI / OpenSpec) |
| Асинхронно | События или webhook; брокер выбирает платформа |
| Файлы | Object storage; версия в пути; префиксы по сервисам |
| Контракты | `FounderHandoff`, `StrategyPublished`, `TalentRoster*`, `HotLeadToCrm`, room-health → Strategy, entitlement/Order |
| Outbox | В PG WowLance для исходящих событий |
| Демо | Standalone: эмуляторы handoff/roster, stubs соседей |

### 8. Правила для кода и ИИ

```text
БД: одна своя на WowLance; чужие БД не читать и не писать SQL
Входит: комната, roster, снимок стратегии, задачи/отчёты, Hot→CRM adapter, API сводок для Стратегии
Не входит в WowLance: Jira, CRM (как продукт), редактор стратегии, Talent-онбординг, биллинг лида
Фаундер-аналитика (WL+CRM) — витрина в Стратегии; WL отдаёт агрегаты
Accept новой стратегии — teamlead
Sale и develop — один room core
```

Наследие 1.0: переносим смыслы (RBAC, Quality Gate, staffing, Hot), не обязаны сохранить Django UI as-is.

## Последствия

**Плюсы:** один кабинет результатов у фаундера (Стратегия); комната остаётся местом команды; границы сервисов простые («своя БД»; Jira и CRM не часть WL); Hot→CRM без второй CRM в комнате.

**Компромиссы:** нужны контракты сводок WL/CRM → Стратегия; менеджер работает в CRM; тяжёлого Jira-аналитического контура нет — сознательно для малых проектов.

**Позже, не сейчас:** опциональная связка с Jira для редких тяжёлых кейсов; детальный состав виджетов фаундера в Стратегии.

## Формулировка для стейкхолдеров

> WowLance — универсальная комната небольшой команды. Фаундер ведёт стратегию и смотрит главные результаты по комнате и продажам в Стратегии; подробности команды — по кнопке в WowLance. У каждого сервиса своя БД. В WowLance не входят Jira и CRM. Горячий лид уходит в CRM. Стратегия в комнате — версией; изменения после старта принимает тимлид.
